# BWU full-faithful integration — design + incremental plan

Routing rqs_lib's receive-path WiFi bandwidth upgrade through nearby-rs's `BwuActor`,
flag-gated behind **`QS_BWU_ACTOR`** (unset = today's proven inline path, zero regression).
beamish/rqs_lib is the BWU **INITIATOR** (offers `UPGRADE_PATH_AVAILABLE` + binds the TCP
listener; the phone dials + is the responder). Derived from the 2026-06-20 mapping workflow.

## Already done (verified, uncommitted)
- **Step A** — `core_lib/src/hdl/ukey_session.rs`: `UkeySession` (Arc, 4 UKEY2 keys, `AtomicI32`
  server/client seq) impls `nearby_rs::bwu::Cipher`; receive path delegates to it; same instance
  survives `set_socket` → seq continuous across the swap. 7 unit tests.
- **Step B.1** — nearby-rs `WifiLanBwuHandler::with_endpoint(sink, bind_ip, advertise_ip)` (no more
  `127.0.0.1`-only). `new` stays loopback. Test added; fmt/clippy/suite green.

## How the two sides actually work (the load-bearing facts)
- **rqs_lib read path** = `handle()` (inbound.rs:240, select! receiver + 4B-BE len read) → `_handle`
  (304, read body) → `process_frame` (322; plaintext `awaiting_introduction` pre-pass + state arms)
  → `decrypt_and_process_secure_message` (677; `UkeySession::decode_payload` + seq pre-incr/`(N vs M)`
  check + `match v1_frame.r#type()` data/BWU demux at 716). Inline BWU arms (911-956) just set
  `upgrade_rejected`/`prior_channel_drained`/`wifi_retry_requested`; the **l2cap.rs driver loop
  (266-409)** polls those flags and runs `offer_wifi_upgrade`/`handover_to_wifi`.
- **nearby-rs BwuActor** NEVER reads a channel itself and NEVER reads data frames. The **consumer**
  reads the old channel and pushes BWU-negotiation frames via `BwuHandle::incoming_frame(pb::OfflineFrame,
  endpoint_id, medium)` (actor.rs:230). The actor reads/writes inline ONLY during the handshake:
  NEW channel = CLIENT_INTRODUCTION read + ACK write (manager.rs:473-486); OLD channel = LAST_WRITE
  write (533), SAFE_TO_CLOSE write (562), DISCONNECTION + 1 drain read + close (582-595); then NEW
  `resume()` + `on_bandwidth_changed(endpoint_id, medium)` (595-597).
- **Construct** with `BwuActor::channel(N)` → `build(rx, handlers, config, local_id)` (NOT `new`) so the
  WIFI_LAN handler's `connection_sink()` exists before the actor. `register_channel` = bare HashMap
  insert (no reader spawned). `run` is `Send` → `tokio::spawn` ok (but see blocking-read risk).

3. **(optional)** Carry the `Arc<dyn EndpointChannel>` (or the raw `TcpStream`) in the completion signal so

4. **`enable_encryption` on the `EndpointChannel` trait** — ✅ **DONE (2026-06-20)**: the trait now has

## Hazards (must address)
- **Two writers on the OLD channel**: actor writes LAST_WRITE/SAFE_TO_CLOSE via `StreamChannel::write`
  while rqs_lib may `encrypt_and_send`/`send_frame` the same socket. → Under `QS_BWU_ACTOR`, route ALL
  registered-channel writes through `EndpointChannel::write` so the single `writer_lock` is authoritative.
- **Two readers**: actor's CLIENT_INTRODUCTION_ACK read + SAFE_TO_CLOSE drain read can steal frames from
  rqs_lib's loop. → rqs_lib is sole reader of OLD (feeds BWU via incoming_frame); actor reads only NEW
  during handshake; rqs_lib starts reading NEW only after `is_upgrade_ongoing` flips false. (Interior
  mutability — borrow checker won't catch it; ownership discipline only.)
- **10s prior-channel stall**: the actor's SAFE_TO_CLOSE path does NOT emit the 25× plaintext KEEP_ALIVE
  nudge (l2cap.rs:209-235) that un-parks the Pixel's parked L2CAP read. → keep rqs_lib's `t_out` nudge
  keyed off the actor's completion, or add a post-close hook to the handler.
- **Seq double-advance**: `UkeySession::decode` (Cipher) advances+enforces client_seq, but inline
  `decrypt_and_process_secure_message` also advances via `get_client_seq_inc`. Under the actor path the
  StreamChannel/Cipher must be the SINGLE seq authority; the inline manual seq advance must be skipped (or
  the channel must use `decode_payload` (no advance) + keep the manual check). Decide per step 1/2.
- **`Medium` of the L2CAP StreamChannel** must report `Medium::Ble` so WIFI_LAN is a valid upgrade target
  (`initiate_bwu` precondition `proposed != channel_medium`, manager.rs:230).

## ★ StreamChannel-adoption inversion — chosen plan (2026-06-20, user's call)

Decision: the live handoff **adopts nearby-rs's `StreamChannel`** for the post-upgrade transfer
(`get_upgraded_channel` + `enable_encryption(session)` + a blocking reader thread), NOT the raw-`TcpStream`/
`set_socket(Tcp)` path. Everything below is **behind `QS_BWU_ACTOR`**; flag unset = today's proven inline path,
**Pixel-validated 2026-06-20** (5.65MB photo, full L2CAP→WiFi upgrade through the UkeySession-refactored crypto,
zero seq errors) — that is the regression baseline.

### Core refactor — split InboundRequest's I/O+crypto from its frame *processing*
Today `InboundRequest::handle()` = read `[4B len]` off `self.socket` → `_handle` reads body → `process_frame`
(plaintext pre-pass) → `decrypt_and_process_secure_message` (`UkeySession::decode_payload` + seq check + the
`match v1_frame.r#type()` data/BWU demux). Writes = `encrypt_and_send` / plaintext `send_frame`.

Under the flag the **`StreamChannel` (an `EndpointChannelBridge` over the existing `proto` duplex, cipher = the
SAME shared `UkeySession`) becomes the I/O + crypto + framing layer**:
- **Reads:** the receive loop calls `channel.read()` → decrypted OfflineFrame bytes (StreamChannel strips the
  4B len, `UkeySession::decode` = `decode_frame`, advancing+enforcing `client_seq`). Feed those bytes to a NEW
  `InboundRequest::process_decoded_frame(bytes)` = the post-decode dispatch ONLY (the body of
  `decrypt_and_process_secure_message` AFTER the decode+seq-check, plus the plaintext handshake pre-pass). The
  inline decode+seq-advance is **skipped** — kills the seq-double-advance hazard (the channel is sole seq authority).
- **Writes:** under the flag `encrypt_and_send` calls `channel.write(frame.encode_to_vec())` (StreamChannel adds
  4B len + `UkeySession::encode` = `encode_frame`, advancing `server_seq`). Single `writer_lock` ⇒ the actor's
  LAST_WRITE/SAFE_TO_CLOSE and our writes can't interleave-corrupt.

### Plaintext→encrypted transition
The UKEY2 handshake frames are plaintext `[4B len][frame]`. So build the bridge **without a cipher** and call
`channel.enable_encryption(session)` at the SAME point `inbound.rs` builds the session / sets `encryption_done`
(~1389). **TODO:** `EndpointChannelBridge::new` currently takes the session and enables encryption in the ctor —
add a plaintext-start variant (or `Option<session>` + enable later). nearby-rs's `enable_encryption` trait seam
(committed) is what makes the later install possible on the `Arc<dyn EndpointChannel>`.

### Actor wiring + upgrade routing
On `State::SentConnectionResponse`: `connection_initiated(ep,false,false)` → `connection_accepted(ep)` →
`register_channel(ep, channel)` → `initiate_bwu(ep, WifiLan)`. The WIFI_LAN handler binds (0.0.0.0, advertise
`lan_ipv4()`); the actor writes the encrypted UPGRADE_PATH_AVAILABLE on the channel — REPLACES
`offer_wifi_upgrade`. Receive-loop demux: a `channel.read()` frame that is BandwidthUpgradeNegotiation →
`bwu.handle.incoming_frame(frame, ep, BleL2cap)`; everything else → `process_decoded_frame`. The actor's accept
loop takes the phone's TCP dial → IncomingConnection → reads CLIENT_INTRODUCTION (plaintext) on NEW + ACK, then
LAST_WRITE on OLD; our `incoming_frame(phone LAST_WRITE)` → actor writes SAFE_TO_CLOSE on OLD; our
`incoming_frame(phone SAFE_TO_CLOSE)` → actor disable_encryption + plaintext DISCONNECTION + drain read + close
OLD + resume NEW + on_bandwidth_changed.

### Hazards (carry from the de-risk test, now live)
- **Two readers of OLD:** once we feed SAFE_TO_CLOSE, STOP reading OLD in the receive loop and let the actor's
  single drain read + close run (poll `is_upgrade_ongoing`). (De-risk test proved the sequencing.)
- **KEEP_ALIVE nudge:** the actor's SAFE_TO_CLOSE path does NOT emit the 25× plaintext KEEP_ALIVE nudge
  (`l2cap.rs` `t_out`, 209-235) that un-parks the phone's parked L2CAP read. RETAIN it: set `upgraded_flag` +
  ensure the actor's OLD-channel close propagates so `t_out`'s relay ends and the nudge fires at convergence.
- **Runtime:** the actor must run on the **multi-thread** runtime (documented on `BwuSession::spawn`) — its
  blocking drain read would deadlock the bridge pumps on `current_thread`. beamish's default runtime is fine.

### Handoff (StreamChannel-adoption)
Poll `is_upgrade_ongoing`==false + `bandwidth_changed_events` has `(ep, WifiLan)` → `get_upgraded_channel(ep)` →
`enable_encryption(session)` (SAME UkeySession ⇒ seq continues, proven offline out 3→4 / in 2→3) → spawn a
**blocking reader thread** over the upgraded channel: loop `channel.read()` → `process_decoded_frame`; route
InboundRequest writes through `channel.write()`. We no longer defer the sharing frame (deferral was removed), so
the transfer just continues on the new channel. Fire the KEEP_ALIVE nudge so the phone unparks.

### Seam needed on InboundRequest
`process_decoded_frame(&mut self, bytes: &[u8])` (post-decode dispatch + plaintext handshake pre-pass) + a
flag-gated write path (`encrypt_and_send`/`send_frame` → `channel.write` when `use_actor`) + receive-loop access
to the channel + the `BwuHandle`.
